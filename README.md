# Task Management API

A Flask REST API for creating, tracking, updating, and deleting tasks. Data persists in SQLite across server restarts. The application separates HTTP routes, validation/business logic, and database access.

## Run locally

Python 3.11+ (PowerShell):

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -m flask --app task_api run --port 5001
```

Default database: Flask's instance directory. Set `TASK_DATABASE` to an absolute path to override it. Startup creates the table without deleting existing records.

## API contract

| Method | Route | Behavior |
|---|---|---|
| GET | /health | Database connectivity check |
| POST | /api/tasks | Create; returns 201 with Location |
| GET | /api/tasks | List, newest first; pagination and status filter |
| GET | /api/tasks/{id} | Read; 404 when missing |
| PATCH | /api/tasks/{id} | Update supplied fields |
| DELETE | /api/tasks/{id} | Delete; returns empty 204 |

Fields: `title` (required on create, 1–120 characters), `description` (optional, up to 2,000 characters), `status` (todo / in_progress / done; default todo). Unknown fields, empty updates, and invalid values return 400. JSON content type is required (415 otherwise); bodies above 16 KiB return 413.

`GET /api/tasks?page=1&per_page=20&status=done` returns `{items, page, per_page, total}`. Maximum page size: 100. Errors use `{"error":{"code":400,"message":"..."}}` and preserve HTTP headers such as Allow.

```powershell
$task = Invoke-RestMethod http://127.0.0.1:5001/api/tasks -Method Post -ContentType 'application/json' -Body '{"title":"Prepare portfolio demo"}'
Invoke-RestMethod "http://127.0.0.1:5001/api/tasks/$($task.id)" -Method Patch -ContentType 'application/json' -Body '{"status":"done"}'
Invoke-RestMethod http://127.0.0.1:5001/api/tasks
```

## Verify

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\ruff.exe check .
.\.venv\Scripts\ruff.exe format --check .
```

Tests cover CRUD, persistence through a fresh app, invalid inputs, pagination/filtering, SQL injection-shaped strings, body limits, and HTTP error behavior.

## Design and limits

- Request-scoped SQLite connections close at teardown; mutations use transactions and bound SQL parameters.
- PATCH uses validated field names and parameterized values. IDs and timestamps are generated by the database.
- Updates use last-write-wins semantics. SQLite suits a small demo; there are no user accounts, authorization, migrations, or multi-tenant isolation.
- Run the development server on localhost. An internet deployment needs authentication and a production WSGI server.
